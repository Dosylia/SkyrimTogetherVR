# Does damage still reduce health, all the way through?
#
# The fix of 2026-09-24: damage is a negative delta and the clients add it, but the server *subtracted* it, so
# every hit raised the health the server kept -- the health it hands out on spawns, hand-offs and respawns.
#
# This checks the client half directly (health falls when damaged, is restored on respawn) and exercises the
# server half by dying and respawning, which is where the server's stored value is handed back.
#
#   powershell -ExecutionPolicy Bypass -File Tools\VR\run-bot-tests.ps1 -Script health-sign.txt
#
# "me" is this bot's own character. Before 2026-09-25 this script asserted against server id 0 and proved
# nothing; it passed whatever the code did.

log Health sign, end to end
waitfor connected 45
collect health death
record health sign

expect players >= 1

log baseline 100
health 100
wait 2
expect health me == 100

log 30 damage: health must fall, not rise
damage 30
wait 2
expect health me == 70
expect health me < 100

log 30 more
damage 30
wait 2
expect health me == 40

log dying takes it to or below zero
die
wait 6
expect health me <= 0

log respawn restores it
respawn
wait 6
expect health me > 0
expect health me <= 100
expect connected

record off
report bot-health-sign.txt
log done
stop
